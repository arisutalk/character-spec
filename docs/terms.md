# Inlay

인레이 에셋은 캐릭터 에셋이 아닌, 캐릭터와 챗 중 생성되는 에셋입니다. 주로 다음 에셋을 포함합니다.

- 유저가 채팅에서 직접 보낸 이미지
- AI가 채팅 컨텍스트를 보고 생성한 배경 이미지
- 봇의 TTS 생성본

감정 에셋과 같은, 모든 채팅에서 공통적으로 사용되는 에셋은 인레이 에셋이 아닙니다.

# 스크립트

스크립트는 캐릭터의 동작을 제어하는 코드입니다. 임의 JS 코드로 샌드박스화되어 실행됩니다.

## Replace 훅

Replace 훅은 스크립트의 서브셋으로, 특정 상황에서 Regex replacing을 수행합니다.

- `request`: AI 요청 직전에, LLM의 컨텍스트를 변경합니다.
- `output`: AI 응답을 변경합니다.
- `input`: 유저의 입력을 변경합니다.
- `display`: 보여지는 텍스트를 변경합니다. 이 훅은 LLM의 컨텍스트나 저장되는 메세지에 영향을 주지 않습니다.

# 플러그인

플러그인은 일부 기능을 사용자 정의할 수 있도록 만들어진 코드입니다. 스크립트와 달리, 플러그인은 샌드박스화되지 않고 실행될 "수도" 있습니다(아직 이 점에 대해서는 미정입니다).
플러그인의 존재 목적은 여러 취향과 장단점이 있는 상황에서 코드로 하나만을 고정하지 않기 위함입니다.

## 레퍼런스 플러그인

퍼스트 파티 플러그인이라고도 불립니다. 레퍼런스 플러그인은 "공식" 플러그인으로, 기본적으로 ArisuTalk에 설치되어 있습니다.
대개 간단한 방식으로 구현합니다.

# 파일

파일의 저장 방법은 두 가지입니다.

- Uint8Array: CBOR으로 export 시에 사용합니다. 이는 export/import 시 base64의 bloat를 방지하기 위함이며, 두 경우를 제외하면 이 방식으로 파일에 접근하는 것은 권장하지 않습니다.
- URL: 파일을 사용할 때 사용합니다.
    - `local`: URL의 커스텀 스키마입니다. 이 경우, 브라우저가 내부적으로 OpFS와 같은 고성능 스토리지에 파일을 미리 옮겨서 저장해두었다고 간주하고 사용합니다. 브라우저는 대개 서비스 워커나 초기 로딩 시점에서 `local` URL을 실제 접근 가능한 URL로 변경하여 사용합니다. 이로써 에셋과 같은 무거운 리소스 없이 가벼운 캐릭터 카드가 완성됩니다.
    - `data`: 절대, 절대, 절대로 사용하지 마세요. 에셋을 카드에 포함시켜서 로딩이 무거워지며 총 용량 또한 커집니다.

# 로어북

작은 지침 조각입니다. 로어북은 이러한 방식으로 개별적으로 활성화됩니다.

- 항상: 이 로어북은 항상 활성화됩니다.
- `plain_text_match`: 문자열 리터럴이 LLM의 컨텍스트에 포함되는 경우 활성화됩니다.
- `regex_match`: 정규식이 LLM의 컨텍스트에 포함되는 경우 활성화됩니다. 성능을 위해 단순 매칭에는 `plain_text_match`를 먼저 사용해주세요.
- `custom`: 커스텀 로어북은 기본적으로 비활성화되어 있지만, "로어북 플러그인"에 항상 보내집니다. 로어북 플러그인이 전적으로 활성화 여부를 결정합니다. 로어북 플러그인이 custom 로어북을 다루지 못할 시, 로어북은 비활성화됩니다. custom 로어북은 서드파티 플러그인을 위해 존재하며, 작동 가능성은 절대로 보장되지 않습니다.

이 경우, 클라이언트는 "활성화된 로어북" 중에서 컨텍스트 예산에 따라 어떤 로어북을 사용할지 선택합니다.

## 로어북 플러그인

로어북 플러그인은 로어북을 활성화하는 방법을 결정하는 플러그인입니다. 로어북 플러그인은...

- 로어북의 활성화 여부를 결정
    - `custom` 로어북의 활성화 판별 포함
- 활성화된 로어북의 순서를 결정

이를 관리합니다. 로어북 플러그인은 로어북의 활성화 여부를 결정할 뿐, 로어북의 내용을 변경하지 않습니다.

어떤 플러그인은 단순 리터럴 매칭을 사용할 수도, 어떤 플러그인은 fuzzy 매칭을 이용해서 정렬할 수도, 어떤 플러그인은 벡터 검색을 사용하여 정렬할 수 있습니다. 로어북 플러그인은 이 방법들을 자유롭게 변경하여 코드에 갇히지 않고 사용자의 취향대로 로어북을 활성화하기 위해 고안되었습니다.

### 레퍼런스 로어북 플러그인

단순 우선순위와 토큰 예산 기반의 로어북 활성화 플러그인입니다. 로어북의 활성화 여부를 결정하고, 활성화된 로어북을 우선순위에 따라 정렬합니다. 이때, 토큰 예산을 초과하는 로어북은 선택되지 않습니다.

#### 예시

예산: 300토큰, 컨텍스트: `ABC`가 포함됨

- 로어북 1: 항상 활성화됨, 우선순위 10, 내용 250토큰
- 로어북 2: plain_text_match(패턴: `ABC`), 우선순위 20, 내용 160토큰
- 로어북 3: regex_match(패턴: `A.C`), 우선순위 -40, 내용 100토큰

1. 로어북 2가 우선순위가 가장 높으므로, 로어북 2가 검사됩니다.
    1. 조건을 충족합니다. 내용도 토큰 예산에 맞습니다. 따라서 로어북 2가 선택됩니다.
2. 그 다음으로, 로어북 1이 검사됩니다.
    1. 조건을 충족하지만, 로어북 2를 선택한 시점에서 예산은 140토큰이 남습니다. 로어북 1의 내용은 250토큰이므로, 예산을 초과합니다. 따라서 로어북 1은 선택되지 않습니다.
3. 마지막으로, 로어북 3이 검사됩니다.
    1. 조건을 충족하지만, 로어북 2를 선택한 시점에서 예산은 140토큰이 남습니다. 로어북 3의 내용은 100토큰이므로, 예산을 초과하지 않습니다. 따라서 로어북 3도 선택됩니다.
4. 최종적으로, 로어북 2와 로어북 3이 선택됩니다.
